搬到另一台电脑时，需要 Python 3.10+、`requirements.lock` 的两项依赖，以及已登录且可用的 Codex CLI。入口复用本机已有模型/provider，不随材料分发凭据。CLI 不在 PATH 时设置 `FDE_CODEX_EXE`。数据、日志默认保存在 `F:\ChatGPT\work\fde-minimum-agent`，可用 `--work` 改到自己的目录。

模型调用需要网络与本机已配置的模型账号额度。每轮最多90秒，每次调查最多5轮；页面显示调查进度。连接不可用时明确显示失败，不把历史回放当新结果。

## 给老师展示的步骤

1. 点“新建正常情景”，看在手12、预留5、可分配7，原8份任务第4分钟完成。
2. 点“登记唯一延期”，系统自动调用真实模型。模型查询快照、任务、规则与来源，比较计划后给出新建议：原8份调整到第8分钟，新增0。
3. 展开真实工具记录，核对模拟迟供从1份降为0份。填写课堂操作者和理由、勾选核对，再采纳。此时在手仍是12。
4. 课堂演示中登记第8分钟完成8份、本窗口累计已履约4份。程序入账为12+8−4=16，预留5，可分配11；剩余模拟需用11份。新事实自动触发新模型调查，读取执行记录后重新评估。
5. 可点“缺制作时间副本”：已知延期风险保留，关键规则缺失时调整量为null，不能采纳。完成登记中的已履约量留空，或只完成部分时，也保留待核实。

这套流程全部是课堂模拟。真实人审记录“核对无误，课堂模拟采纳调整原待办”仍只对应旧案例摘要；本轮自动验收操作另标“测试操作者”，没有冒充用户签审或企业执行。

## AI实际做什么

经营事件触发 → 模型选择白名单查询/模拟工具 → 程序真实执行 → 结果反馈模型 → 模型形成当前建议 → 制作岗位决定 → 实际完成/履约登记触发模型重新评估。

这不是仅用AI开发程序，也不是只回放旧AI结果。模型的作用是根据当前状态选择查证、比较路径与形成建议；数量计算与业务写入由确定性程序检查。只有人员界面可以采纳、改量、忽略和登记完成。

运行方式是“结构化下一工具 → 宿主执行 → 反馈模型”的应用层工具协议，不宣称是模型API原生function_call事件。Codex CLI 的[官方非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)提供 JSONL 与 JSON Schema 输出；本程序不调用CLI内建shell、子代理或联网工具，保留内部read-only沙箱。配置依据见[官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。

## 数据与计算

- `inputs/`是已提交输入的校验复制：课堂快照、唯一CloudEvents延期、公开种子记录、来源许可、逐字段来源和SHA256清单。真实采集继续仅用Scrapling；本轮无新采集。
- 来源：Cazier, Spaulding, Hassler (2025), [Sandwich Analytics V1](https://data.mendeley.com/datasets/9hntk3wbwc/1)，CC BY 4.0。源商品1023、商品记录35741、收据记录3836；源数据不能提供本案例的库存、在制与分钟需求。
- 库存、需用时点、制作4分钟、有效可售时间及执行均是课堂假设。公开前缀不是连续样本，不能据此拟合真实高峰强度。
- `projection.py`复用既有SimPy计算口径：分钟单位，先到期、后供给、再需用；包含第20分钟，最多32业务事件/256调度步，守恒检查。没有随机分布拟合或收益推断。
- 预测不扣库存；采纳不入库；完成入账一次；批次有效期单独保留。预留量与新增模拟需用分别处理。到期排除不等于实际报废，迟供不等于真实丢单。

| 文件 | 用途 |
| --- | --- |
| `server.py` | 127.0.0.1服务、界面/API、本地操作令牌 |

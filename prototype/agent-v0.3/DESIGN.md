# 最小运行切片 v0.3

沿用 v0.2 的一店、一商品与唯一延期事件。新增运行时模型入口、本地事务、人审及完成后复评。不改变已提交 v1 附件。

## 界面

延续既有演示的深绿与浅底，面向制作岗位；主视觉是一条需用/完成时间线。左侧显示当前经营状态和模型建议，右侧是核对与完成登记，下方展开真实工具记录。

- 色彩：底色 #F5F5EF，正文 #172D32，主色 #1A6752，分隔 #D5DEDB，风险 #A35019，风险底 #FFF0DC。
- 字体：微软雅黑，标题 28px，正文 15px，证据 12px。
- 左对齐；桌面两列、手机一列。时间线说明延期与调整的业务关系，不放装饰图。
- 主操作按步骤出现：登记延期 → 模型调查 → 人员确认 → 模拟完成登记 → 模型重新评估。

## 模型与工具

Codex CLI 为本机原型的模型适配器，复用已配置模型和认证。每次调用只输出严格 JSON；shell、多智能体、插件与不需要的 MCP 关闭，内部 sandbox read-only。程序执行白名单业务函数，不执行模型给出的命令。模型先选择证据，再调用比较工具，最后生成建议。最多5轮、每轮90秒；失败不使用旧回放代替。

模型可用工具：get_snapshot、get_evidence（任务、规则、来源）、compare_plans、get_execution。写操作始终由人员界面调用，服务端再次检查版本、数量、证据与幂等键。

## 数量和事实

初始在手12、预留5，可分配7。延期原8份从第4分钟改第12分钟。未来需用是课堂假设，不能当作实际订单自动扣库。采纳只改原任务，不入库。

完成登记可同时提供“本窗口累计已履约量”。例：第8分钟完成8份、已履约4份，账面在手12+8−4=16，预留5，可分配11；剩余模拟需用11。新批次单列有效截止第38分钟，旧批次截止第28分钟。模型读取新版本与执行记录重新评估。已履约留空时，已过去的4份需用保持待核对，不能关闭风险。少完成时，剩余任务ETA未知，不能默认已完成。

本切片完成时点限第5～9分钟（第二个需用时点前）；不声称已实现任意时间推进、真实POS接入、多人身份认证或生产权限。

## 证据与限制

输入复用现有 Scrapling 真实采集、字段来源、CloudEvents 事件和模拟参数。没有新爬取、批量模拟或数据扩充。SimPy 4.1.2有事件/步数上限，先到期、后供给、再需用，包含第20分钟。使用既有 SimPy 与 data-quality-frameworks 技能的有界调度、数据契约、唯一性与一致性检查方法。

SQLite 保存当前状态、人审、执行、模型运行及工具结果；重复请求无二次入库，旧版本建议不得采纳。模型文本保留原文；可采纳数量必须与当前版本的工具输出一致。

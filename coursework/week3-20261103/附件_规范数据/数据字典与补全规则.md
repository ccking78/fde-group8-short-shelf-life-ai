# 数据字典与补全规则

本文件描述课堂契约v1.0.0，不提供未观测经营参数。记录中的null必须有missing_reasons，不能解释为0。

## 真实记录

|字段组|内容|来源与处理|
|---|---|---|
|observed|receipt_id store_id date start_time end_time item_id quantity_raw return_raw drive_thru_raw|保留E1/E3原值，见必要选列证据与逐字段来源|
|menu|matched item_name category_id category_name subcategory_id subcategory_name|按Inv_Num匹配E4；未匹配时5个描述字段null并注明原因|
|derived|quantity is_return drive_thru start_local_time end_local_time start_hour weekday_iso|数量与布尔解析；当地时间格式化；日期派生。不是厨房或顾客履约时间|
|unknown|source_timezone kitchen_completed_at service_due_at actual_on_hand actual_prep_minutes actual_capacity_per_batch actual_sellable_minutes|全部保留null。公开文件无相应观测，不用课堂假设替代|
|missing_reasons|JSON Pointer到code和reason的映射|每个null一一对应；not_in_source或no_menu_match|
|record_id evidence_id contract_version|源记录身份、选列引用和版本|E3数据行序号稳定生成；不是模拟订单ID|

## 课堂快照

state保持已确认课堂切片；field_origins逐叶登记。只有source_item_id引用真实商品，其他状态、映射和规则均为课堂假设。相对分钟从课堂窗口0起算，单位为份与分钟。

## 模拟增量

唯一活动事件见05文件，CloudEvents结构化JSON。source+id是事件身份，主体TASK-8，data包含前值4、后值12、前版本0、后版本1。event_minute与recorded_minute为相对分钟1；未填写绝对time。规则为本课堂契约；不扩充事件种类。

同source+id同内容忽略；同source+id不同内容拒绝；不同来源同id不当作重复，但不在本切片登记的来源不能写入。新事件须通过字段、实体引用、时间顺序、版本、前值及快照约束，全部成功才提交。

## 缺规则测试

06为故意缺制作时长的测试覆写，作用于事件后版本1，不是新业务增量。只把prep_minutes改为null；不能因补全动作将它恢复为4。

## 来源与规范

- [W3C Data on the Web Best Practices](https://www.w3.org/TR/dwbp/)：许可、逐字段来源、质量报告、版本与修改历史、缺失原因、覆盖限制和衍生规则。
- [JSON Schema Validation Draft 2020-12](https://json-schema.org/draft/2020-12/json-schema-validation)：使用Draft202012Validator；显式启用本契约的日期、当地时间及UTC登记时间检查。
- [RFC 3339 Internet Timestamps](https://www.rfc-editor.org/rfc/rfc3339)：系统登记时间用带Z的UTC格式；原交易只有当地钟表时间，保留原值且时区为空。
- [CloudEvents Specification v1.0.2](https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/spec.md)：事件携带id、source、specversion=1.0和type；source与id组合去重；只有相对分钟时省略time。
- [python-jsonschema 4.25.1 validation documentation](https://python-jsonschema.readthedocs.io/en/v4.25.1/validate/)：固定依赖版本；本地schema检查和离线重放，不联网解析远程schema。

# 第8组 · 短保商品供需错配 AI 提醒

**D1 交付版本：2026-10-21**  
方向：国际连锁餐饮品牌 AI 原生零售门店 · 课题：AI经营异常提醒

## 我们要解决的问题

在销售高峰开始前，帮助当班店长识别短保商品的缺货与剩余风险，调整本轮新增供给。业务范围包括生鲜、烘焙与即食餐品；首版聚焦一店一品、一个高峰、一次供给调整。

确定性程序计算数量、时间、批次和成本；大模型整理证据、解释依据；店长确认后执行。拟记录 `event_at` 与 `known_at`，保证决策仅使用当时已知的信息。

## 数据入口与使用边界

先读 [数据说明](data/d1/先读说明.md)，再查看 [七张 CSV](data/d1/数据) 和 [原始快照及许可](data/d1/原始来源)。

| 来源 | 已采集范围 | 可以支持什么 | 关键限制 |
| --- | --- | --- | --- |
| FreshRetailNet-50K | 门店0、商品38/834/411；各90日，共270商品日、6480小时格，2024-03-28至2024-06-25 | 小时销量与缺货标记、观察销售和时间信息核对 | 数量经过缩放；缺货标记不是库存数量，销量不是完整潜在需求；匿名商品不能改名为鸡腿饭 |
| Reduce-Foodwaste-Dataset | 9家匿名连锁烘焙门店；5142条训练日记录、1575条留后记录与官方 truth 一对一连接 | 日销量、订货、余货字段及真实缺失示例 | 三列不能默认共同尺度；unsold不等于报废，ordered不等于生产批次；truth只能用于留后评价 |

首轮主序列固定为 Fresh 门店0、商品38（90日、2160小时），按采集顺序选首条完整序列。两数据源独立使用，不能把匿名门店编号连接为同一家门店。小时数据不拆成伪真实15分钟流水。

真实批次、有效库存数量、温控与可售寿命、成本、13点后售卖规则尚未取得。文档中的鸡腿饭、12份/批、45分钟、2小时及成本参数均为情景假设，不能写成门店真实操作规范。

## 本地复现

需要 Python 3.9 或更高版本。以下脚本仅使用标准库，无需联网或安装依赖。在仓库根目录运行：

```powershell
python "data/d1/复现脚本/rebuild_data.py" --output-dir "work/rebuilt-d1"
python "scripts/verify_scenario.py"
```

第一条从随包原始快照重建七张 CSV；第二条核对 D1 情景演算，结果写入 `work/scenario/calculation_check.json`。原核查结果见 [情景复核记录](checks/scenario_calculation_check.json)；这不代表预测模型准确率、系统联调或真实经营收益已经通过验收。原始交付文件哈希见 [来源校验记录](checks/d1_source_integrity.json)。

同一明示情景下，新增0/1/2/3批的比较损失分别为420.60/252.36/84.12/59.88元，推荐3批；若12至13点的16份需求全部在12:30前到达，2批的损失低于3批。建议依赖需求时序，不能声称3批普遍最优。
